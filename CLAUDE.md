# oncalendar

A Rust library that parses systemd calendar event expressions (`OnCalendar=`), prints their normalized form, and computes when they elapse next. Public, dual-licensed `MIT OR Apache-2.0`. The design is in `docs/architecture.md`.

## Language

- Everything committed to this repository is English: code, comments, docs, commit messages, PR text.
- Conversation with the maintainer follows the maintainer's global settings.

## No comments

- Code, scripts, and configuration carry no comments. Names and structure say what the code does, and the reasons go in `docs/architecture.md` or the commit message.
- The one exception is `///` and `//!` documentation in `src/`, because it is the published API reference.
- The `#` lines in `tests/fixtures/*.tsv` are section titles of the fixture format, not comments.
- `scripts/check-no-comments.sh` enforces this. It runs in `verify gates` and in CI.

## Clean room (license rule, not a preference)

systemd is LGPL-2.1-or-later. This crate is not.

- Do not open, search for, quote, or port systemd source code or its tests, or the source of any other implementation of this grammar, in any language.
- The only sources of truth are the systemd manual (`systemd.time(7)`, "Calendar Events") and the observable output of `systemd-analyze calendar`.
- When behavior is unclear, ask the oracle: add cases and run `oracle/run.sh`. Do not guess and do not read the implementation.
- Do not copy manual text into the repository beyond short example expressions.

## Verification

- Use the `verify-oncalendar` skill (`.claude/skills/verify-oncalendar/SKILL.md`) before claiming a change works. A change to parsing, normalization, or scheduling is proven by `verify compare` reading `differing: 0`, not by unit tests alone.
- `tests/fixtures/expected.tsv` is generated by the oracle. Never edit it by hand. Regenerate with `oracle/run.sh < tests/fixtures/cases.tsv > tests/fixtures/expected.tsv`.
- A new behavior starts as new rows in `tests/fixtures/cases.tsv`.

## Weight and security

- The crate must stay light. `default-features = false` compiles zero other crates. A new dependency needs a raised limit in `scripts/check-weight.sh` and a reason in `docs/architecture.md`.
- Input is untrusted. The library has no `unsafe`, does not panic, bounds its input, and does not echo input in error messages. The lints in `Cargo.toml` enforce the first and catch the common panics, and the robustness tests cover the rest. Do not add `#[allow]` or `#[expect]` in `src/`. `scripts/check-security.sh` rejects it.
- Parsing reads no file and no environment variable. Only the `jiff`-gated modules (`zone`, `next`) may touch the time zone database.
- Run `scripts/check-security.sh` and `scripts/check-weight.sh` before a commit that touches `src/` or `Cargo.toml`.
